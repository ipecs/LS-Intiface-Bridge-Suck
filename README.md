# LS Intiface Bridge

Android 12+ bridge between Intiface's Device WebSocket Server and LoveSpouse/MuSe BLE advertising devices. Version 1.3 targets Android 15 and emulates a Lovense Nora with vibration and rotation controls. Remove the old Hush device from Intiface and scan again if its cached capabilities remain. Intiface's device server uses port 54817; a normal Buttplug client uses its separate server port.

The bridge uses one persistent legacy advertising set, serializes asynchronous updates and retains only the current desired state. Manufacturer ID is `0xFFF0`; the payload prefix is `6DB643CE97FE427C`. Vibration maps inputs 0–2 to stop, 3–4 to command 1, 5–9 to command 2 and 10–20 to command 3.

Suction follows rising intensity events. It receives values from 0 to 20 through Vibrate, or through Rotate when the vibration-source switch is disabled. It does not receive original funscript positions or timestamps, so its events describe the received intensity rather than exact movement positions. The script and manual test now share the selected suction command; the default is command 2. The old automatic mapping between commands 1, 2 and 3 has been removed because their physical effects have not been established as power levels.

The default trigger threshold is 3. After enabling suction, a fresh low sample establishes a baseline; if the first sample is already high, a new fall and rise are required. A rise of at least 2 points to a value at or above the threshold triggers one sequence. A fall of at least 2 points, or a fall below the threshold, rearms detection even while the sequence is busy. A subsequent rise above the threshold can trigger without falling all the way below 5. At threshold 1 the rise requirement is 1 point. Constant high values do not retrigger. Busy events are counted and consumed immediately, never queued for late replay. The display shows input intensity, requested triggers, busy events and the active stage; logs identify each accepted or skipped rise.

The primary pulse is configurable from 0.7 to 5 seconds. Its timer starts after Android accepts the positive command, and duplicate callbacks or incoming values cannot extend it. A sparse stream does not cut an accepted suction pulse after 1.2 seconds; the bounded pulse completes. Vibration retains its independent 1.2-second remote-input expiry. A lost WebSocket connection, explicit Stop, Off, settings change or disabling suction cancels the sequence. Separate Rotate:0 also cancels it; a zero from the vibration source only rearms event detection. Suction begins disabled on every Start.

An optional experimental second pulse is available only for command 2 and starts disabled by default. A user reports that after a 2.3-second command-2 suction, pressing command 2 again briefly starts the pump and releases retained vacuum. The exact duration and repeatability of that effect have not been verified. The option tests a fixed serialized sequence: primary pulse, accepted stop and configured pause, another command-2 pulse for 1 second after Android accepts its data, then accepted stop and configured final rest. The primary pulse is capped at 4 seconds when this option is enabled, keeping total requested pump-on time at most 5 seconds. The intermediate pause and final rest each use the existing stop-hold setting. A 2.3-second primary pulse, 1-second pause, 1-second second pulse and 1-second final rest occupy about 5.3 seconds plus Android/radio latency. This cannot execute every faster script event; events during the whole sequence are explicitly skipped. No old timer can operate on a new sequence: one state machine owns every stage, and cancelling it removes the pending positive step.

Verify the complete double-pulse test outside the body before enabling it for a script. The second positive command is an experimental release attempt, not a known valve-open opcode or a guarantee of venting. A manual suction test pauses script outputs until Start, so the script cannot interfere with or repeat the test. Off disables suction and pauses remote outputs until Start. Start disables suction again before accepting future activation.

The global stop button disconnects Intiface, advertises `E5157D` for a fresh full stop hold, then sends vibration stop and closes the bridge. Its protocol reference is [pylovespouse OFF()](https://github.com/RevenantFreddy/pylovespouse/blob/main/lovespouse.py). The user reports that this command does not release vacuum on their HB2451. It remains a stop operation and must not be treated as pressure relief. BLE callbacks confirm Android accepted data, not that the toy received it. The protocol exposes no hardware acknowledgement, pressure or battery telemetry; software timers cannot guarantee physical release after a radio, Android or firmware failure.

Build and test with JDK 17:

```sh
./gradlew testDebugUnitTest assembleDebug
```

GitHub Actions performs both steps and uploads the debug APK. The package identity is unchanged; a debug APK signed with a different key requires uninstalling the existing app before installation.
